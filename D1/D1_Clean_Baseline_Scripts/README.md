# Скрипты чистой базовой конфигурации D1 — обновлённая топология стенда

Этот пакет подготавливает **эталонную базовую конфигурацию без ошибок** для поиска и устранения неисправностей в модуле D1 на обновлённой топологии стенда, представленной на снимке экрана.

Это не пакет для внесения неисправностей. Сначала примените его, проверьте полную связность и работу служб, а затем создайте чистый снимок/контрольную точку, например с именем `D1-CLEAN-UPDATED`.

## Используемые имена устройств топологии

Сетевые устройства:

- `HQ-GW1`, `HQ-GW2`, `HQ-SW`, `HQ-SW-D`, `HQ-R`
- `DC-GW`, `Switch`
- `Internet`, `MPLS`
- `DC1`, `DC2` в облачном ЦОД

Конечные узлы:

- HQ: `HQ-WS01`, `HQ-AD01`, `HQ-FILE01`, `HQ-LNX01`
- DC: `DC-LNX01`, `DC-LNX02`, `DC-CL01`, `DC-Win01`, `DC-SVC01`

## Политика адресации

На всех маршрутизируемых соединениях «точка — точка» используется `/30`, а не `/31`, чтобы учебная базовая конфигурация оставалась понятной и была совместима с большим числом образов эмуляторов.

## MPLS в D1

`MPLS` реализован как **упрощённый маршрутизируемый WAN-сегмент провайдера**. Полный стек MPLS L3VPN намеренно не используется в базовой конфигурации D1, поскольку D1 — это смешанное учебное задание на знакомство с топологией и устранение неисправностей базовой конфигурации. Поведение, аналогичное MPLS, реализовано за счёт меньшей стоимости OSPF для пути MPLS по сравнению с путём через Internet.

## Рекомендуемый порядок запуска

1. Примените конфигурации Cisco из `cisco/` согласно `docs/RUN_ORDER.md`.
2. Настройте узлы Windows с помощью скриптов из `windows/`.
3. Настройте узлы Debian с помощью скриптов из `linux/`.
4. Запустите проверки из `validation/`.
5. Исправьте несовпадения имён интерфейсов, зависящие от образа.
6. Сохраните конфигурации и создайте чистые снимки.
7. Применяйте скрипты внесения неисправностей D1 только после проверки этой базовой конфигурации.
